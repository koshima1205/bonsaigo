# BONSAIGO（ボンサイゴー）— 盆栽の知恵を、世界へ。次の百年へ。

Built with Claude: Japan 2026（2026-11-02〜11-08）の提出作品です。チーム Chakobond（ちゃこボンド）。
このリポジトリの旧名は Engawa です。中身はすべて会期中に作ったものです。

## 解きたい課題
盆栽の知恵は人から人へ受け継がれてきました。いま日本では後を継ぐ人が少なく、その知恵は園の中に閉じたまま消えかけています。海外の愛好家と日本の職人のあいだには、3つの壁があります。

1. **認知**：海外から園が見つからない。発信が得意でない職人も多い
2. **言葉**：相談する人は日本語が分からず、職人は外国語で答えられない
3. **継承**：知恵が記録されずに消えていく

数字で見ると（一次資料で確かめたもの）
- 盆栽の輸出額は 3.4億円（2020年）から 9.0億円（2025年）へ（農林水産省「花きの現状について」2026年6月・元は財務省 貿易統計）

https://www.maff.go.jp/j/seisan/kaki/flower/attach/pdf/index-128.pdf

- 盆栽の産地・高松の盆栽農家は 286戸（2000年）から 199戸（2015年）へ、15年で約3割減（高松市「高松盆栽の郷」基本構想 2017年）

https://www.city.takamatsu.kagawa.jp/jigyosha/sangyou/nogyo/bonsai.files/28753_L21_satokousou.pdf

## BONSAIGO でできること
- 海外の人が、自分の言葉と写真で園に相談する。職人には日本語で届く
- 職人は、書いても声でも答えられる。Claude が答えを意味で訳し、日本語に訳し戻してずれを確かめ、職人が OK したものだけが届く
- やり取りは Q&A としてたまり、どの言葉からでも探せる
- 職人は写真を撮って OK を押すだけで、公式の X・Instagram 向けの多言語の投稿文ができる（アプリから自動では投稿しない。確かめを通った文を、私たちが公式アカウントから出す）

## 動かし方
```
cd 盆栽マッチング_箱崎の試作/盆栽マッチング_動く試作_2026-11-05
npm install
cp .env.example .env
chmod 600 .env
npm start
```
- `.env` に `ANTHROPIC_API_KEY` を入れると本物の Claude で動きます（使った分の料金がかかります）
- 公開するときは `ACCESS_PASSWORD` を必ず入れます
- 見本の職人は架空の人物です

## アプリの中の Claude
| しくみ | 何をする |
|---|---|
| 相談の言い換え | 相談する人の言葉と写真を、職人が使う日本語に直す。写真の見立ても添える |
| 答えの下書きと整え | 職人の答えを読みやすく整える。下書きを出すこともあるが、採用・手直しは職人が決め、職人が送るまで何も届かない |
| 意味で訳す＋訳し戻し | 直訳ではなく意味で訳し、日本語に訳し戻して、ずれがないかを確かめてから届ける |
| 用語の札 | 専門の言葉に触ると、意味と「なぜそうするか」が出る |
| Q&A と窓口 | たまった Q&A から近い答えと出どころを探す（AI を呼ばない検索で料金ゼロ）。なければ「この問いを園に聞く」 |
| 発信の下書き＋2段の確かめ | 写真と言葉から多言語の投稿文を下書きし、画像（盆栽か）→ 文の2段で確かめる |
| 料金の守り | 確かめは Haiku 5.5、書くのは Sonnet 5.5、確かめが通らないときだけ Opus 5.5。プロンプトキャッシュ。1人1日12回・全体1日200回の上限 |

料金の実測（2026-11-08）：アプリと同じ指示文・同じ写真と文で、デモの流れ1回分（AI を7回呼ぶ）を「全部 Opus」と「今の使い分け」で2回ずつ流し、API が返したトークン数から料金を出しました（アプリのコードはそのまま）。

| | 全部 Opus | 使い分け | 減り |
|---|---|---|---|
| 料金（指示文の使い回しなし） | $1.050 | $0.284 | -73% |
| 料金（使い回しあり） | $0.323 | $0.093 | -71% |
| かかった時間 | 126〜140秒 | 64〜74秒 | 約半分 |

- 確かめる3つの役（答えの見直し・写真の確かめ・投稿文の確かめ）は、どれも -97%。書く4つの役（相談の訳・答えの下書き・職人の言葉の訳・投稿文づくり）は -50〜58%
- 写真の確かめと投稿文の確かめの判定は、Opus と同じでした。答えの見直しだけ、Opus は「自信がないので人が確かめる」、Haiku は「直しが必要」と分かれましたが、どちらもそのまま通ることはありませんでした
- 見積もり（100人・1人あたり相談3回と窓口の質問10回・1ドル150円）では、全部 Opus で月約11,800円のところ、約3,000円です

## 開発での Claude の使い方
2人がそれぞれ Claude Code（CLI・Desktop）を開発の中心にして作りました。目的に合わせて、次のように使い分けています。

| 使ったもの | 何のために | 場所 |
|---|---|---|
| サブエージェント（3つの立場） | 職人・海外の愛好家・審査員の立場から、画面と動画に反論させる。3つとも「職人が言っていない言葉が職人の名前で届く」を一番に挙げたので、答えの案は園の記録だけから作り、記録の番号を付ける形に変えた | `.claude/agents/persona-*.md`・`docs/review_3personas.md` |
| サブエージェント（検品） | 人に見せる前に、画面・資料・README を100点で採点させ、90点未満なら直す所を返させる | `.claude/agents/kenpin.md` |
| スキル | 3つの立場の反論を同時に回し、直す所を1枚にまとめる | `.claude/skills/persona-review/` |
| フック | 鍵のファイルを読ませない。GitHub への push・公開・まとめて消す操作は、必ず人に確かめる | `.claude/hooks/guard.py`・`.claude/settings.json` |
| モデルの使い分け | 設計の芯と最後の検品は上位のモデル、実装はふだんのモデル、検品のくり返しは軽いモデル。アプリの中でも、確かめは Haiku・書くのは Sonnet・通らないときだけ Opus | `盆栽ゴー_料金の守り.mjs`・`docs/cost.md` |
| MCP | 3D の庭と盆栽の模型づくり（Blender）、2人の連絡（Slack） | 前身の版の記録 |
| Claude.ai の Artifacts | 提出物の一覧やデザインの見本を2人で見て、コメントで直しを集める | — |

## 試行錯誤の流れ
最初からこの形だったわけではありません。くわしくは `docs/decision.md`（日付・理由・捨てた案）にあります。

1. 11/4：盆栽メディア「Engawa」として、記事24本×5言語・用語集・掲示板など10の機能を作りきった
2. 11/5：歩いて回れる 3D の日本庭園を作った
3. 11/6：機能が増えすぎ、何の課題を解いているのか説明できなくなった。狙いを「すでに盆栽を育てている海外の人」に絞り、3D の庭は入口から外した
4. 11/7：盆栽園の職人にお話を伺い、課題を一つ、壁を三つ（認知・言葉・継承）に整理し直した。2人の版を1本にまとめ、名前を BONSAIGO にした
5. 11/8：職人がスマホで、写真を撮って OK を押すだけで使える形に仕上げた（このリポジトリの提出版）

前身の版のコードは、このリポジトリの過去のコミット（11/4〜）に残っています。
